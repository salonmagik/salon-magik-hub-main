**Coverage caveat that qualifies every statement below:** this pass ran with real `sk_test_` Paystack credentials against both the local stack (Tier B) and the dev Supabase project (Tier A), closing most of the credential-blocked gap the prior run recorded. `create-payment-session` (`PAY-BOOK-OK-*`) and the deployed webhook signature verification (`PAY-TRANSPORT-*`) now have real, passing evidence against Paystack's live test-mode API. What remains genuinely unproven, and could not be closed in this pass regardless of credentials: (1) `refund-via-paystack`'s own initiating call (`REF-a`) requires a transaction that itself came from a completed hosted-checkout charge — nothing in this harness can drive that without a human at a browser (design AD-R4); (2) the payout transfer-*initiation* calls (`W-DUP-REQ`, `W-FLOOR`, `W-OTP`) are gated on the same Tier A precondition but were never implemented against `paystack-test-client.ts` in this pass — the precondition is met (a real key is present) but no call was made, and that is recorded honestly as not-run, not assumed passing.

**(a) Payout path — go/no-go: NO-GO (a specific, confirmed defect, not a coverage gap).**
What passed for real, now including a genuine attempt against the actual guard logic: `PAYOUT-W-OK-{GHS,NGN}`, `PAYOUT-W-FAILED-{GHS,NGN}`, `PAYOUT-W-REVERSED-{GHS,NGN}`, `PAYOUT-W-DUP-EVT-{GHS,NGN}`, `PAYOUT-AUTH-NONMEMBER-{GHS,NGN}`, and — new in this pass — `PAYOUT-W-OVER-{GHS,NGN}` all pass. What remains unevidenced: FR-18 (`W-DUP-REQ`) and FR-20 (`W-OTP`) are still **unevidenced** — both require a transfer actually initiated against Paystack, which this pass's harness does not attempt (see coverage caveat). `W-FLOOR` (also FR-19, alongside the now-passing `W-OVER`) is unevidenced for the same reason.

Per AD-10's note for the verdict author, this does not by itself force a no-go on `subaccount-split-cleanup` (C-3 is independent of the split/subaccount code that cleanup removes) — but it is a real, now triply-confirmed (static read, local RPC call, dev-project RPC call) payout-path defect, and "go" on the payout path cannot be said while it stands, independent of the W-DUP-REQ/W-FLOOR/W-OTP coverage gap.
