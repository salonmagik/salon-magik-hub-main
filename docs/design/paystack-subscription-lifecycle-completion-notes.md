# Notes — Paystack Subscription Lifecycle Completion

Design: `paystack-subscription-lifecycle-completion.design.md`
Review: `.claudespace/s/4aa44ffc-6670-4070-adba-f7ce52c4a274/reports/paystack-subscription-lifecycle-completion-review.md` (verdict: PASS, round 2)

- Built: owner-initiated end-of-period cancellation/resume, a time-bounded grace period after exhausted retries ending in suspension, and Chain-annual pricing moved onto the same self-managed billing engine as every other plan/cycle (with a dry-runnable migration function for existing Chain-annual tenants).
- `compute_chain_price`'s return shape was kept as-is (`total_price, breakdown, requires_custom`) rather than the design's sketched 4-tuple — the existing shape has 7 call sites reading fields by name; a `p_billing_cycle` parameter was added instead, achieving the same data-gating (AD-8) intent without breaking anyone.
- `is_tenant_operational`'s replacement correctly discovered and preserved the `tenant_trial_overrides` precedence from an earlier migration the design's own sketch omitted — worth remembering as an example of implementation-time verification catching a design gap.
- `tenants.billing_grace_started_at` was added beyond the design's column list — needed to make AD-7's per-grace-episode dunning-notice keying well-defined once `BILLING_GRACE_PERIOD_DAYS` is configurable.
- Round 1 review found one BLOCKER (masked "Card on file" display, requirement 22, was missing entirely) and several IMPORTANT test-coverage gaps against the design's named test list. All were fixed and independently re-verified in round 2 (tests actually run, SQL actually executed against a reset local Postgres, not just re-read).
- Round 4 closed the round-2 residual gap: `manage-subscription-cancellation`, `verify-recurring-billing-retry-session`, and `migrate-chain-annual-billing` were extracted into injectable-client `handleX(...)` core functions (mirroring `lifecycle.ts`/`charge.ts`), each now with real, independently-run-and-passing Deno tests (28/28). `deno test` was also actually executed for the first time (Deno installed locally) rather than traced by hand.
- Round 4 also added a real, executed (not mocked-away) Playwright e2e suite for the three flows the design named (AC 1/2/3) — network-mocked against a fake origin with a hard throw-on-any-real-`supabase.co`-request safety net, since this sandbox's local Supabase has no Auth/Kong/PostgREST. 3/3 passed, 6/6 on a repeat-each=2 run, independently reproduced.
- That e2e work found a real, pre-existing, unrelated bug: a `blocking: true` "Payment Failed" full-screen overlay in `BannerContext.tsx` for `subscription_status === 'past_due'` (with no route exception) made every route — including the subscription page itself — unreachable for a past_due owner, directly contradicting this feature's own AD-4 ("past_due must stay operational during grace"). Neither code-review round caught it because neither rendered the real app. Fixed by deleting the dead overlay in favor of `BillingStateBanner`. Worth remembering: a "run the app for real" pass caught something two rounds of careful code review structurally could not.
- Deferred by design, not by omission: Implementation Order items 19-20 (entering real annual Chain pricing in backoffice, running `migrate-chain-annual-billing` for real) are gated on a commercial pricing decision that doesn't exist yet — AD-8 makes this a data condition, not a code flag, so it can ship whenever that decision lands with no further deploy. No live-Paystack-sandbox exercise of the migration function has happened yet for this reason.
- Operational note, not a code issue: this branch's working tree was shared with a concurrent, unrelated pipeline session (`feat/refund-card-clawback-safeguard`) during round 4, with no worktree isolation between them. Nothing was lost (the concurrent session stashed correctly), but worth setting up worktree isolation for future multi-feature pipeline runs against this repo.
